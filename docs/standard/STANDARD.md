# Стандарт кодування та довідник конструктивних практик CafeOrders

Версія 1.0.0 · діє з 01.10.2026 · власник — автор проєкту (ведучий розробник)

## 1. Сфера дії, рівні обов’язковості, глосарій

### 1.1. Сфера дії

Стандарт поширюється на весь код рішення `CafeOrders`: бібліотеку логіки `CafeOrders.Core`,
консольний застосунок `CafeOrders.App` і проєкти тестів `*.Tests`. Стандарт **не** поширюється на
згенерований код (`obj/`, `*.g.cs`), на навмисно «поганий» навчальний код у теках `Legacy/`, який
вносять для вправ із рефакторингу, і на гілки-пісочниці з префіксом `sandbox/`, що не зливаються в `main`.
Попередні версії правил, ухвалені в ЛР1 (`CODING_STANDARD.md`), цим документом замінено.

### 1.2. Рівні обов’язковості

| Рівень | Значення | Наслідок порушення |
| :--- | :--- | :--- |
| ОБОВ’ЯЗКОВО | виконують завжди | збірка падає (`error`) або зміну не приймають на огляді |
| РЕКОМЕНДОВАНО | виконують, якщо немає вагомої причини вчинити інакше | зауваження на огляді, причину відступу пишуть у коментарі |
| ДОПУСКАЄТЬСЯ | обидва варіанти прийнятні | зауважень не роблять |
| ЗАБОРОНЕНО | конструкція в проєкті не вживається | збірка падає або зміну не приймають |

### 1.3. Нумерація правил

`N` — іменування, `F` — форматування, `C` — коментарі й документація, `D` — дані й типи,
`S` — керуючі конструкції та складність, `A` — машинна частина, `X` — правила предметної області
кав’ярні. На огляді коду пишуть «порушено N-07», а не «мені не подобається».

### 1.4. Шаблон запису правила

Кожне правило має шість полів: ідентифікатор і формулювання, рівень, обґрунтування, порушення,
дотримання, спосіб перевірки. Правило без способу перевірки — побажання; його або доводять до
перевірного вигляду, або знижують рівень до РЕКОМЕНДОВАНО з перевіркою «пункт чекліста».

### 1.5. Глосарій предметної області

## 2. Іменування ідентифікаторів

**N-01. Простір імен починається з `CafeOrders`, далі — назва проєкту й тека.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: простір імен збігається з розташуванням файлу, тож тип знаходять без пошуку.
Порушення: `namespace Domain;` у файлі `CafeOrders.Core/Domain/Order.cs`.
Дотримання: `namespace CafeOrders.Core.Domain;`. Перевірка: IDE0130, рівень warning; глибина — не більше 4 сегментів, пункт чекліста.

**N-02. Клас, структура, запис — PascalCase, іменник однини з глосарія.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: одне поняття — одне ім’я, інакше пошук `Order` не знайде `Zakaz` і `Bill2`.
Порушення: `class zakaz`, `class OrderData`. Дотримання: `class Order`. Перевірка: IDE1006 (стиль іменування типів), рівень error; відповідність глосарію — чекліст.

**N-03. Інтерфейс — `I` + PascalCase, що описує можливість або роль.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: префікс одразу відрізняє абстракцію від реалізації в сигнатурі конструктора.
Порушення: `interface OrderStorage`. Дотримання: `interface IOrderRepository`. Перевірка: IDE1006, error.

**N-04. Приватне поле — `_camelCase`; статичне `readonly`-поле — `s_camelCase`.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: підкреслення миттєво відрізняє поле від локальної змінної, тому зайвим стає `this.`.
Порушення: `private decimal total;`. Дотримання: `private decimal _total;`. Перевірка: IDE1006, error.

**N-05. Константа — PascalCase без префіксів; `SCREAMING_CASE` заборонено.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: конвенція .NET; константа читається як властивість-факт (`VatRate`).
Порушення: `const decimal VAT_RATE`. Дотримання: `const decimal VatRate`. Перевірка: IDE1006 (правило `const_pascal`), error.

**N-06. Перелічення — PascalCase в однині; члени — PascalCase; прапорці `[Flags]` — у множині.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: змінна `OrderStatus status` читається природно, `OrderStatuses status` — ні.
Порушення: `enum OrderStatuses { NEW }`. Дотримання: `enum OrderStatus { New }`. Перевірка: CA1714, CA1717, IDE1006.

**N-07. Метод — PascalCase, дієслово або дієслівна фраза; запит без побічних ефектів може мати суфікс `Of`.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: ім’я відповідає на питання «що станеться після виклику».
Порушення: `Calc()`, `ProcessData()`. Дотримання: `CalculateTotal()`, `SubtotalOf(lines)`. Перевірка: пункт чекліста R-01.

**N-08. Асинхронний метод має суфікс `Async`.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: виклик без `await`
видно з імені. Порушення: `Task<Menu> LoadMenu()`. Дотримання: `Task<Menu> LoadMenuAsync()`. Перевірка: IDE1006 (правило `async_suffix`), warning.

**N-09. Булева властивість, поле, метод-запит — з префіксом `Is`, `Has`, `Can`; метод-спроба — `Try…` з `out`.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: `if (order.IsPaid)` читається як речення; `Try` попереджає, що невдача — не виняток.
Порушення: `bool Paid`, `bool Chg(int n)`. Дотримання: `bool IsPaid`, `bool TryChangeStatus(OrderStatus next)`. Перевірка: чекліст R-01.

**N-10. Локальна змінна й параметр — camelCase, повне слово; однолітерні імена — лише лічильник `for`.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: `l`, `t`, `x` неможливо знайти пошуком і зрозуміти без читання тіла методу.
Порушення: `foreach (var x in l)`. Дотримання: `foreach (OrderLine line in lines)`. Перевірка: IDE1006 (регістр), чекліст R-01 (зміст).

**N-11. Колекція — іменник у множині; словник — `XByY`.** Рівень: РЕКОМЕНДОВАНО.
Обґрунтування: множина сигналізує «тут кілька», `ByCode` — за яким ключем шукати.
Порушення: `List<MenuItem> menuItemList`, `Dictionary<string, MenuItem> dict`. Дотримання: `menuItems`, `menuItemsByCode`. Перевірка: чекліст R-01.

**N-12. Параметр узагальненого типу — `T` або `T` + PascalCase.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: конвенція .NET.
Порушення: `Result<V>`. Дотримання: `Result<T>`, `IRepository<TEntity>`. Перевірка: CA1715, error.

**N-13. Подія — дієслово в минулому або тривалому часі; делегат-обробник — суфікс `Handler`.** Рівень: РЕКОМЕНДОВАНО.
Обґрунтування: подія повідомляє про факт. Порушення: `event OrderPay`. Дотримання: `event EventHandler<OrderPaidEventArgs> OrderPaid`. Перевірка: CA1710, чекліст.

**N-14. Тестовий метод — `Метод_Умова_Результат`, тестовий клас — `<КласПідТестом>Tests`.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: назва впалого тесту в журналі CI пояснює, що зламалося, без відкриття коду.
Порушення: `Test1()`. Дотримання: `Total_RegularGuestAbove1000_AppliesTenPercent()`. Перевірка: чекліст R-14; підкреслення в іменах тестів дозволено придушенням CA1707 лише для тестових проєктів.

**N-15. Ім’я файлу збігається з іменем єдиного типу у файлі.** Рівень: ОБОВ’ЯЗКОВО.
Обґрунтування: тип знаходять за деревом тек. Порушення: `Code1.cs` з класом `Bill`. Дотримання: `Bill.cs`. Перевірка: SA1649 і SA1402, error.

**N-16. Абревіатури з двох літер — великими (`IO`), довші — як слово (`Json`, `Csv`).** Рівень: РЕКОМЕНДОВАНО.
Обґрунтування: конвенція .NET, `JsonMenuStore` читається легше за `JSONMenuStore`. Перевірка: чекліст.

### 2.1. Заборонені антипатерни іменування

| Антипатерн | Погано | Добре | Чим шкідливо |
| :--- | :--- | :--- | :--- |
| ім’я-затичка | `data`, `info`, `temp`, `item1` | `menuItem`, `orderLines` | нічого не каже про зміст |
| транслітерація | `Zamovlennya`, `kolvo` | `Order`, `lineCount` | не знаходиться пошуком англійською, змішує мови |
| угорська нотація | `strName`, `iCount`, `lstLines` | `name`, `count`, `lines` | дублює тип, бреше після зміни типу |
| нестандартне скорочення | `calcOrdTot`, `cl` | `CalculateOrderTotal`, `guestName` | кожен розшифровує по-своєму |
| ім’я з `And` | `SaveAndPrintBill` | `Save`, `Print` окремо | ознака двох обов’язків |
| беззмістовний суфікс | `OrderManager`, `MenuHelper`, `Utils` | `OrderService`, `MenuPricing` | клас без чіткої відповідальності розростається |
| числовий суфікс | `Calculate2`, `OrderFinal` | `CalculateWithDiscount` | не каже, чим відрізняється від «1» |
| ім’я, що бреше | `GetTotal()`, що ще й зберігає | `CalculateTotal()` + `Save()` | читач не чекає побічного ефекту |

### 2.2. Приклади «погано / добре»

```csharp
// ПОГАНО
public decimal Calc(List<OrderLine> l, int t)
{
    decimal s = 0;
    foreach (var x in l) s += x.UnitPrice * x.Quantity;
    if (t == 2) s = s * 0.9m;
    return s;
}

// ДОБРЕ
public decimal CalculateTotal(IReadOnlyList<OrderLine> lines, GuestTier tier)
{
    decimal subtotal = 0m;
    foreach (OrderLine line in lines)
    {
        subtotal += line.Amount;
    }

    return _pricing.ApplyDiscount(subtotal, tier);
}
```

Пара 1. `Calc` не каже, що обчислюють; `l` і `t` не знаходяться пошуком; `t == 2` — магічне число,
зміст якого знає лише автор. Тип `GuestTier` унеможливлює передавання випадкового числа.

```csharp
// ПОГАНО
public bool Flag { get; set; }
if (order.Flag == true) { ... }

// ДОБРЕ
public bool IsPaid => Status == OrderStatus.Paid;
if (order.IsPaid) { ... }
```

Пара 2. `Flag` не пояснює, що позначено; порівняння з `true` нічого не додає; публічний сетер дозволяє
«оплатити» замовлення в обхід правил переходу станів.

```csharp
// ПОГАНО
public class zakaz { public string cl; }

// ДОБРЕ
public sealed class Order
{
    public string GuestName { get; }
}
```

Пара 3. Транслітерація й скорочення `cl` (клієнт? колір? клас?) змушують читача шукати місце використання.

```csharp
// ПОГАНО
private List<MenuItem> lstMenu;
private Dictionary<string, MenuItem> d;

// ДОБРЕ
private readonly List<MenuItem> _menuItems = new();
private readonly Dictionary<string, MenuItem> _menuItemsByCode = new();
```

Пара 4. Угорський префікс `lst` бреше, щойно список стане масивом; `d` не каже, за яким ключем шукати.

```csharp
// ПОГАНО
public void SaveAndPrintBill(Bill bill) { ... }

// ДОБРЕ
public void Save(Bill bill) { ... }
public string FormatReceipt(Bill bill) { ... }
```

Пара 5. `And` в імені — дві причини змінювати метод: формат чека й спосіб зберігання.

```csharp
// ПОГАНО
public decimal GetTotal(Order order)
{
    decimal total = order.Lines.Sum(line => line.Amount);
    _repository.Save(order);   // побічний ефект, якого не видно з імені
    return total;
}

// ДОБРЕ
public decimal TotalOf(Order order) => order.Lines.Sum(line => line.Amount);
```

Пара 6. Ім’я «отримати» обіцяє запит, а метод змінює сховище — виклик у звіті непомітно перезапише дані.

```csharp
// ПОГАНО
public class MenuHelper
{
    public static decimal Calculate2(MenuItem item, int q) { ... }
}

// ДОБРЕ
public sealed class ComboPricing
{
    public decimal PriceOf(ComboMeal combo) { ... }
}
```

Пара 7. `Helper` і `Calculate2` не називають відповідальності; такий клас стає звалищем статичних методів.

```csharp
// ПОГАНО
enum OrderStatuses { NEW, IN_WORK, DONE }
const int MAX_LINES = 100;

// ДОБРЕ
enum OrderStatus { New, Preparing, Served }
const int MaxLineCount = 100;
```

Пара 8. Множина в імені перелічення й `SCREAMING_CASE` суперечать конвенціям .NET і аналізаторам CA1714, IDE1006.

```csharp
// ПОГАНО
public interface OrderStorage { }
public class Repo : OrderStorage { }

// ДОБРЕ
public interface IOrderRepository { }
public sealed class InMemoryOrderRepository : IOrderRepository { }
```

Пара 9. Без префікса `I` у сигнатурі `OrderService(OrderStorage s)` не видно, чи це абстракція; `Repo` не каже, де зберігає.

```csharp
// ПОГАНО
[Fact]
public void Test1() { ... }

// ДОБРЕ
[Fact]
public void TryChangeStatus_PaidToNew_ReturnsFalse() { ... }
```

Пара 10. Повідомлення CI «Test1 failed» нічого не каже; друга назва описує метод, умову й очікування.

```csharp
// ПОГАНО
public void Add(string s, int k, decimal c) { ... }

// ДОБРЕ
public void AddLine(string menuCode, int quantity, decimal unitPrice) { ... }
```

Пара 11. Підказка IntelliSense `Add(s, k, c)` не допомагає викликачу; другий варіант документує себе сам.

## 3. Форматування, структура файлу, коментарі

### 3.1. Форматування й структура файлу

**F-01. Відступ — пробіли, табуляція заборонена.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: табуляція показується різною шириною в різних редакторах і в diff на GitHub. Перевірка: `indent_style = space`, IDE0055, error.

**F-02. Відступ — 4 пробіли на рівень; у `.csproj`, `.props`, `.json`, `.yml` — 2.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: конвенція .NET; XML і YAML глибоко вкладені, 2 пробіли економлять ширину. Перевірка: `indent_size`, IDE0055.

**F-03. Кінці рядків — LF, кодування — UTF-8 без BOM.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: однаковий diff у Windows і в Linux-конвеєрі CI; ЛР1 показала, що без правила `dotnet format` створює мішані кінці рядків. Перевірка: `end_of_line = lf`, `charset = utf-8`, `.gitattributes`.

**F-04. Довжина рядка — не більше 100 символів.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: на екрані 1920 пікселів у режимі порівняння двох версій із відкритою панеллю провідника видно близько 105 символів шрифту 14 пт, тож 100 гарантує відсутність горизонтального прокручування на огляді. Довший рядок розривають за F-11. Перевірка: `max_line_length = 100` (підказка редактора) і пункт чекліста R-03; у CI — `awk 'length > 100'`.

**F-05. У кінці файлу — рівно один символ нового рядка; пробілів у кінці рядків немає.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: інакше diff показує «зміну» останнього рядка. Перевірка: `insert_final_newline`, `trim_trailing_whitespace`, SA1028, error.

**F-06. Фігурні дужки — стиль Allman.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: пара дужок стоїть на одній вертикалі, межі блоку видно без підсвітки. Перевірка: `csharp_new_line_before_open_brace = all`, IDE0055.

**F-07. Дужки обов’язкові для тіла `if`, `else`, `for`, `foreach`, `while`, навіть з однієї інструкції.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: найчастіша помилка — дописати другу інструкцію під `if` без дужок. Перевірка: `csharp_prefer_braces = true:error`, SA1503.

**F-08. Між членами класу — рівно один порожній рядок; два порожні рядки поспіль заборонені; після закривної дужки блоку — порожній рядок.** Рівень: ОБОВ’ЯЗКОВО. Перевірка: SA1516, SA1507, SA1513.

**A-04. Код у теках `Legacy/` має окрему секцію `.editorconfig` з пом’якшеними правилами.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: навчальний «поганий» код має збиратися, щоб його можна було рефакторити під тестами; сфера дії — розділ 1.1.

**A-05. Придушення діагностики дозволене лише в `.editorconfig` з коментарем-обґрунтуванням або атрибутом `SuppressMessage` з непорожнім `Justification`; `#pragma warning disable` у тілі коду заборонено.** Рівень: ОБОВ’ЯЗКОВО. // ПОГАНО

```csharp
// ДОБРЕ
[SuppressMessage(
    "Design",
    "CA1062:Validate arguments of public methods",
    Justification = "Order створює лише OrderFactory, яка вже перевірила аргумент")]
public decimal TotalOf(Order order) => order.Lines.Sum(line => line.Amount);
```

Пара 25. `#pragma` вимикає правило мовчки й до кінця файлу; атрибут обмежує дію одним методом і пояснює причину.

## 7. Чекліст огляду, порівняння з публічними стандартами, порядок змін

### 7.1. Чекліст огляду коду

Чекліст лежить у файлі `REVIEW_CHECKLIST.md`. Пунктів, які перевіряє машина (відступи, `using`,
дужки, документація), у ньому немає.

### 7.2. Культура огляду

1. Зауваження формулюють до коду, а не до автора: «цей метод змінює стан», а не «ти зламав».
2. Кожне зауваження виконуване: містить дію й номер правила — «винесіть 0.9 у константу (D-04)»,
   а не оцінку «незрозуміло».
3. Зауваження з префіксом «nit:» — дрібниця, яку автор може не виправляти.

### 7.3. Порівняння з публічними стандартами

| Питання | Microsoft C# Coding Conventions | dotnet/runtime C# Coding Style | Наш стандарт | Чому так |
| :--- | :--- | :--- | :--- | :--- |
| Приватне поле | `_camelCase` | `_camelCase`, статичне `s_` | `_camelCase`, статичне `s_` (N-04) | префікс знімає потребу в `this.` |
| `var` | коли тип очевидний | лише коли тип названо праворуч | лише коли тип названо праворуч (D-03) | явність типу для команди-початківців |
| Довжина рядка | жорсткої межі немає | жорсткої межі немає | 100, чекліст + awk (F-04) | **відступ 1**, див. нижче |
| Дужки для однієї інструкції | рекомендовано | дозволено без дужок, якщо в один рядок | обов’язково, error (F-07) | **відступ 2**, див. нижче |
| Стиль дужок | Allman | Allman | Allman (F-06) | збіг з обома джерелами |
| Відступ | 4 пробіли | 4 пробіли | 4 пробіли, LF (F-01…F-03) | LF через Linux-конвеєр CI |
| `int` проти `Int32` | ключові слова мови | ключові слова мови | ключові слова мови (IDE0049) | збіг |
| Розташування `using` | поза простором імен | поза простором імен, `System` першими | поза простором імен, `System` першими (F-13) | збіг |
| Простір імен | file-scoped | file-scoped у нових файлах | file-scoped, error (F-12) | менше відступів |
| Порядок членів | не регламентовано | поля на початку | константи, поля, конструктори, властивості, методи (F-10) | стан класу видно першим |
| XML-документація | для публічного API | для публічного API | для всіх публічних членів Core, error (C-06) | **відступ 3**, див. нижче |
| Константи | PascalCase | PascalCase | PascalCase (N-05) | збіг |
| Суфікс `Async` | так | так | так (N-08) | збіг |
| `nameof` | рекомендовано | обов’язково замість літералів | обов’язково в винятках (S-02) | рядок з іменем ламається при перейменуванні |
| `#region` | не згадано | не використовуються | заборонено, error (F-14) | регіон ховає завеликий клас |

**Відступ 1 — жорстка межа рядка 100.** Обидва джерела жорсткої межі не ставлять. Ми ставимо, бо огляд
коду ведемо у режимі порівняння двох колонок на екрані 1920 пікселів: довший рядок вимагає
горизонтального прокручування, і зміна в його кінці лишається непоміченою. Ціна правила — ручне
перенесення кількох рядків на тиждень.

**Відступ 2 — дужки навіть для однієї інструкції, рівень error.** Настанови dotnet/runtime дозволяють
пропускати дужки для однорядкового тіла. У навчальному проєкті зміни вносять швидко й часто, а
найпоширеніша помилка початківця — дописати другу інструкцію під `if` без дужок (див. пару 13). Ціна
правила — один-два зайві рядки; ціна помилки — дефект, якого не видно під час читання.

**Відступ 3 — документація для всіх публічних членів бібліотеки, рівень error.** Microsoft і dotnet/runtime
вимагають документацію для публічного API, що його використовують інші. У нас бібліотеку `Core`
використовує лише власний застосунок, але курс вимагає, щоб тест і документація описували контракт
методу; з рівнем error конвеєр не пропустить новий публічний метод без опису.

### 7.4. Порядок внесення змін до стандарту

1. Запропонувати зміну може будь-хто з команди — у вигляді issue з міткою `standard` або pull request
   до `docs/standard/STANDARD.md`.
2. Пропозиція містить: формулювання правила за шаблоном 1.4, обґрунтування, приклад «погано / добре»,
   спосіб машинної перевірки (або пункт чекліста) і оцінку вартості приведення наявного коду в годинах.
3. Рішення ухвалює ведучий розробник після обговорення з командою; принцип — консенсус, а за його
   відсутності правило не вводиться (статус-кво перемагає).
4. Рішення фіксується записом у `DECISIONS.md` з номером, датою, альтернативами й наслідками.
5. Версія стандарту — за семантичним версіюванням: нове правило рівня РЕКОМЕНДОВАНО або уточнення
   формулювання — молодша (1.0 → 1.1), підвищення рівня правила або нове ОБОВ’ЯЗКОВЕ правило —
   старша (1.x → 2.0), виправлення помилки в тексті — патч (1.0.0 → 1.0.1).
6. Перехідний період: наявний код не переписують одномоментно; діє правило бойскаута — файл, якого
   торкнулися, лишають чистішим, ніж він був. Порушення в незачеплених файлах записують до реєстру
   боргу з терміном погашення не пізніше двох тижнів (або до наступної лабораторної роботи).
7. Шкідливе правило скасовують тим самим порядком: пропозиція з доказом шкоди (скільки часу
   забирає, скільки хибних спрацювань), запис у журналі рішень, підвищення старшої версії, а у
   `.editorconfig` правило переводять у `none` з коментарем-посиланням на номер рішення.

## 8. Правила предметної області: склад страви й колекції в публічному інтерфейсі

Найлегше помилитися там, де замовлення, меню й комплексні страви віддають назовні свої колекції:
стороння зміна списку обходить правила переходу станів і перерахунку ціни.

**X-01. Склад комплексної страви (`ComboMeal.Components`) — незмінна колекція, задана в конструкторі; додати чи вилучити компонент після створення неможливо.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: ціна комплексу розрахована на конкретний склад; зміна складу «на льоту» дає ціну, якої немає в меню. Порушення: `public List<MenuItem> Components { get; set; }`. Дотримання: `public IReadOnlyList<MenuItem> Components { get; }` з копією в конструкторі (`components.ToArray()`). Перевірка: CA1002, CA2227 (error), тест незмінності.

**X-02. Агрегат віддає колекцію лише як `IReadOnlyList<T>` над приватним полем; змінювати її можна тільки методами агрегату (`AddLine`, `RemoveLine`), які перевіряють стан.** Рівень: ОБОВ’ЯЗКОВО. Порушення: `public List<OrderLine> Lines => _lines;` (викликач зробить `order.Lines.Clear()` у стані `Paid`). Дотримання: `public IReadOnlyList<OrderLine> Lines => _lines;`. Перевірка: CA1002, чекліст R-06.

**X-03. Метод, що приймає колекцію лише для читання, оголошує параметр як `IReadOnlyList<T>` або `IEnumerable<T>`, а не `List<T>`.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: сигнатура обіцяє, що метод не змінить список гостя. Перевірка: CA1002, чекліст.

**X-04. Метод не повертає `null` замість порожньої колекції: «нічого не знайдено» — це `Array.Empty<T>()` або порожній список.** Рівень: ОБОВ’ЯЗКОВО. Обґрунтування: викликач робить `foreach` без перевірки, а `null` дає падіння у звіті «популярність позицій». Перевірка: тест «порожній результат», чекліст R-06.

**X-05. Колекцію добирають за операцією: пошук позиції меню за кодом — `Dictionary<string, MenuItem>` з `StringComparer.OrdinalIgnoreCase`; набір унікальних кодів — `HashSet<string>`; впорядкований склад — `List<T>`/масив.** Рівень: РЕКОМЕНДОВАНО. Обґрунтування: пошук у списку з 300 позицій меню — лінійний, і `"esp-001"` не знайде `"ESP-001"`. Перевірка: чекліст R-05.

```csharp
// ПОГАНО
public sealed class ComboMeal
{
    public List<MenuItem> Components { get; set; } = new();
    public decimal Price { get; set; }
}

combo.Components.Add(dessert);   // ціна комплексу лишилася старою

// ДОБРЕ
public sealed class ComboMeal
{
    private readonly MenuItem[] _components;

    public ComboMeal(string code, IEnumerable<MenuItem> components, decimal price)
    {
        ArgumentNullException.ThrowIfNull(components);
        _components = components.ToArray();
        if (_components.Length < MinComponentCount)
        {
            throw new ArgumentException("Комплекс має містити щонайменше дві позиції.", nameof(components));
        }

        Code = code;
        Price = price;
    }

    public string Code { get; }

    public decimal Price { get; }

    public IReadOnlyList<MenuItem> Components => _components;
}
```

Пара 26. У першому варіанті будь-хто додає компонент і отримує десерт безкоштовно; у другому склад
фіксується під час створення, а копія масиву захищає від зміни вихідного списку викликачем.

```csharp
// ПОГАНО
public List<OrderLine> FindByMenuCode(string code)
{
    if (!_index.ContainsKey(code)) return null;
    return _index[code];
}

// ДОБРЕ
public IReadOnlyList<OrderLine> FindByMenuCode(string code)
{
    return _index.TryGetValue(code, out List<OrderLine>? lines)
        ? lines
        : Array.Empty<OrderLine>();
}
```

Пара 27. `null` замість порожнього списку (X-04) і змінюваний `List` назовні (X-02) в одному методі.
